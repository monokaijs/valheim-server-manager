# Admin world map and player teleport

Open **World map** as a dashboard administrator. Moderators, anonymous visitors and external API tokens have no map or teleport access. Terrain and player endpoints use the existing Steam session and revalidated admin role; teleport also uses the existing CSRF header. Samples stay in memory, are not written to the player-history database, and are not sent through the general SignalR hub or webhooks. Map responses carry `Cache-Control: no-store`.

## Runtime requirements

Install/build the manager/dashboard and the server agent from this working tree together. The server agent produces terrain and position samples. Players need the **updated companion client from this working tree** to receive teleport commands; the existing published 2.7.2 client does not advertise the new `VSM_MapHello` capability and is shown as requiring an update. This work intentionally does not bump the release version, publish a package or install into a running server. The compatibility checker remains read-only: external mod managers handle installation.

Valheim owns player movement on the player's client. Teleport is sent only over that player's authenticated server-peer RPC and uses the locally owned `Player.TeleportTo` path. Server-side ZDO position writes are not used. Replicated positions and completion replies come from the owning game process; they are not anti-cheat attestation. Position visibility is independent of the in-game public-position toggle because admins receive server-replicated character state.

## Map and coordinate conventions

The map refines to **2048 × 2048 pixels at 12 metres/pixel**, using actual biome heights, forest masks, shoreline/depth ramps and directional terrain lighting from the active `WorldGenerator`. A 256 × 256 initial preview appears first; 64 independently transferred 256 × 256 detail tiles progressively replace it, starting near spawn. The 24,576-metre square extent and texel-centre offsets match the linked WebMap convention. Palette/shore/lighting work is adapted from [h0tw1r3/valheim-webmap](https://github.com/h0tw1r3/valheim-webmap/) under MIT; its notice is retained in `docs/licenses/valheim-webmap-MIT.txt`. This integrates rendering, not that project’s public HTTP server. X points east/right, Z points north/up, Y is height, all in game metres. World identity uses the native 64-bit world UID encoded as a string; the seed is not published. The actionable circle is 10,000 metres from the origin, leaving a margin inside the game's lethal edge. The map shows generated natural terrain, not buildings, exploration fog, interiors, dungeons or terrain edits. Actual terrain edits/collision are checked by the receiving client once its target area loads.

Sampling stays on Unity's main thread in slices of at most 128 samples / a two-millisecond budget per update (a single engine call can exceed the budget). Generation occurs once per loaded generator/world. Map frames replace a single latest-frame buffer every second; offline/reconnecting managers do not accumulate a map backlog. Float32 little-endian heights preserve terrain precision. Serialization runs off-thread and each tile stays below the existing 2 MiB transport limit. Serialized preview/tiles are cached and sent once per manager connection; a generator revision invalidates caches even when the same world UID reloads. Complete first-time generation can take several minutes under the bounded tick budget. Dashboard position polling is sequential and pauses while hidden. An independent cancellable terrain loader prevents large tile transfers from stalling positions. This is sampled telemetry, not a per-server-tick movement stream. Missing ZDOs show loading; dead players cannot teleport. Missing agent or five seconds without a fresh frame shows disconnected/stale state and disables actions. World changes invalidate terrain; disconnect retains faded last-received markers until fresh state arrives. Losing authorization clears the displayed data.

## Teleport flow

Select a player, then enter X/Z and optional Y, or drag their marker to a destination. A drop **only stages a destination**. Confirm in the destination dialog to send it. Escape, pointer cancellation, a drop outside the map, or Cancel sends nothing. Coordinate entry provides a keyboard-accessible alternative to dragging.

Requests include an exact string peer ID, platform ID, random connection-session ID, world ID and command UUID. The manager and server recheck identities, freshness, finite coordinates and the circular bound. They refuse missing capability, loading/dead players, pending teleports and scheduled disconnects. The client additionally checks local ownership, character bootstrap/death-save state, cutscene/intro/attachment, native teleport state and cooldown. Death-safe saves and backup logic are unchanged.

Destinations must be dry natural terrain. Blank Y selects ground automatically. A supplied Y must be near the generated surface and ultimately between 0.5 and 2 metres above the loaded floor; it is honoured when safe. Ocean, steep floor, obstructed capsule, unexpected world/session/character changes and missing floor are refused. Valheim's non-distant native teleport loads the destination and can return to its origin when no floor exists. After loading, the client raycasts the actual floor, tests slope/water level and capsule clearance, and returns an actual position only after successful placement. On a failed final check it attempts a native return to the recorded origin. A timed-out native area load is aborted by restoring the still-owned local player to its origin and resetting the verified native teleport fields; the client advertises capability only when these fields exist with the expected types. Return is best-effort if the player dies, disconnects, or ownership changes. Safe checks are limited to supported outdoor terrain and static collision; they do not guarantee protection from combat, falling dynamic objects, biome hazards or a modified game process. A live game acceptance session is still required.

Only one command per peer can be pending. Same UUID/actor/payload retries share one task/result for ten minutes and cannot resend the game RPC; altered payloads are rejected. Failures and unknown outcomes are also retained. This deduplication is in memory, so it does not survive manager restart. A timeout/disconnect is **unknown**, not success. Check the refreshed player position before creating a new command. The manager audits request/result with actor, world, coordinates and command UUID, without agent/session credentials. Client success is acknowledged after loading/validation; RPC dispatch alone is never reported as success.

## Validation

- `dotnet test ValheimServerManager.slnx`: coordinate edge/nonfinite validation, dead/loading/capability checks, exact IDs, world/session/reconnect invalidation, terrain isolation, duplicate concurrent commands, unknown results and audit records, plus real HTTP anonymous/mod/admin and CSRF checks. Existing character backup/death fence tests remain in the suite.
- Build both plugin projects with `ValheimManaged` and `BepInExRoot` pointing to local game references.
- `npm ci --prefix web && npm run build --prefix web`.
- `npm run test:map --prefix web`: Playwright mocked dashboard tests for drag cancellation/Escape, pointer cancellation, invalid coordinates, repeated confirmation, coordinate axes, reconnect/world change, stale/auth states, zoom/pan, Float32 decoding, shoreline/forest shading, tile boundaries and desktop/mobile layout. Run `npx playwright install chromium` in `web` if needed, or set `VSM_TEST_BROWSER` to an existing Chromium executable. Screenshots are fixture data, not a real world.

Before an authorized release/deployment, use a disposable local/test world with two clients to verify loaded/unloaded destinations, modified terrain, rejected collision/water/slope, death/loading, attached players, cooldown, lost RPC acknowledgments, client disconnect/reconnect and safe return. No live-world files or actual players were changed for this implementation.
